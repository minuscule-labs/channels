# MinuChannels v0.0.17

Compared with **v0.0.16**, this update adds images to Conversation messages and delivers their pixels to compatible owned Pi agents.

## Share images inside a Conversation

Choose images with the composer attachment button, paste them from the clipboard, or drop them into the composer. Send an image on its own or alongside text.

- Supports **PNG, JPEG, GIF and WebP**: up to **four images**, **10 MiB each** and **20 MiB combined** per message.
- Keeps image order, renders bounded previews with accessible open-image actions, and provides a safe unavailable-image fallback.
- Preserves completed-upload metadata and the exact retry key/payload after ambiguous sends, including reload/retry, without uploading again or duplicating the message.
- Persists message associations and image files across reopen. Pending upload bytes cannot survive navigation; abandoned staged uploads expire after 24 hours.
- Continues blocking arbitrary Markdown images. This is sharing within local Conversation messages, **not public links, anonymous access or cross-machine synchronization**.

## Let a compatible agent inspect the pixels

Owned Pi sessions can receive bounded raster image parts when their **currently active model** advertises image input. Relay selects images from the existing Conversation context and Fresh-session boundary, favors recent/trigger images, and preserves their order within the per-turn count/byte limits.

Image content travels through authenticated generated-ID reads and typed Runtime input, not a host path or an unauthenticated browser URL. Unsupported, old, attached-TUI, unknown and text-only sessions keep explicit unavailable-image markers rather than silently claiming vision. Native Pi/model-provider pixel handling remains responsible for decoding and any normal image transformation.

Native Pi may retain image parts in its owner-private prompt transcript and submit them to the configured provider, as with other prompts. Runtime turn polling, normalized message projections, public text/SSE and structured diagnostic events do not expose those pixel payloads.

## Retry and cancellation safeguards

Runtime turn identity covers text plus ordered image bytes/MIME. Recovering an accepted turn does not refetch or redispatch it.

Accepted pre-dispatch turns remain cancellable while transcript or final model-capability reads are pending. Late reads are fenced from sending a canceled prompt or altering a later turn. Execution ownership uses the exact turn instance, so eviction and reuse of a caller ID cannot let an old finalizer clear newer admission or interrupt state. Existing uncertainty handling remains in place after a native interrupt is actually requested.

## Storage and upgrade safety

A new public Conversation migration, **0009**, adds attachment metadata/associations without rewriting existing message text. Image bytes live outside SQLite in owner-private `attachments/` under the product data directory; `--data-dir` relocates them with the databases. Migration snapshots include image files, and standalone databases have isolated orphan sweeps so they cannot delete one another's message images.

Back up the **complete stopped data directory** before upgrading, and restore its databases, profile and image files together. Downgrading migrated data is unsupported; no automatic rollback or secure-erasure guarantee is added. Native Pi transcripts remain separate private Runtime data.

Runtime advances to pinned commit `e33b8a2da639832947b1bb203b45be5cc40d0772`, merged through [Runtime PR #11](https://github.com/minuscule-labs/runtime/pull/11). Local-control protocol **22**, optional diagnostic-journal schema **2**, and authoritative Relay schema are unchanged from v0.0.16.

## Verification and known limitations

The feature merged in [Channels PR #48](https://github.com/minuscule-labs/channels/pull/48) after Ubuntu/macOS verification, full Chromium regression and release-package CI passed. Controlled tests cover storage/reopen, image-aware retries, capability fallback, cancellation, stale-read fencing and turn-ID reuse. Packaging checks exercise the bundled Runtime client/worker through controlled Pi RPC; focused independent review approved the final bounded turn-instance fix.

Two explicitly approved genuine-agent image turns passed on `openai-codex/gpt-6.1-sol` using Pi **0.99.1** and disposable data. Both replies matched all four generated color/shape pairs, including a different image after app reopen. Tools/extensions/context discovery were disabled, and temporary processes/data were removed. See [sanitized real-Pi evidence](../verification/image-vision-real-pi.json) and the [image implementation/evidence](../image-support.md).

- Those real-agent checks used the current account and compiled product gateway/agent host. They are **not clean-account macOS/Linux acceptance, an interactive manual-browser run or acceptance of a newly installed full release package**. Published-artifact validation remains a separate release-completion requirement.
- The earlier intermittent native database-related panic still has no proven root cause. A native-binding abort recurred in post-merge CI; this release does **not** claim to fix it. Failed verification must be resolved or explicitly investigated before publication, not hidden by disabling tests.
- Container/signature checks are not full pixel decoding. Corrupt content can still fail to render or be rejected by the harness/provider. Vision was checked on the observed model, not every supported provider/model.
- MinuChannels remains a single-user, loopback-only local alpha for macOS and Linux. Do not expose its ports to other machines or untrusted local users. Hosted authorization/storage, generic files, audio and external Markdown images are not included.

## Installing or upgrading

Download `minu-channels-0.0.17.tgz` and `SHA256SUMS` from the approved GitHub Release, verify the checksum, then install:

```bash
npm install -g ./minu-channels-0.0.17.tgz
```

Follow [installation and upgrade guidance](https://github.com/minuscule-labs/channels/blob/v0.0.17/docs/local-release.md) to coordinate a running instance and back up its data. **Publishing this release does not upgrade or restart any installation.**
