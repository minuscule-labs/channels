# MinuChannels v0.0.33

This release fixes retained local proxy/SSE resources and includes the Workspace/Conversation settings and UUIDv7 changes merged since v0.0.32. Only merged source is included; unrelated local working-tree changes are excluded.

## Connection cleanup

Browser disconnects now terminate their upstream production-proxy exchanges. Premature upstream failure terminates the downstream response so existing clients can reconnect. Cancellation disposes of fully parsed but unread response bodies while preserving healthy upstream socket reuse and normal JSON, binary, HEAD, and streaming completion.

Both Conversation event routes release subscriptions and heartbeat timers when a client disconnects, setup fails, a response errors, or the server shuts down. A subscription resolving after disconnect or shutdown immediately disposes itself rather than starting another stream or heartbeat.

The investigation demonstrated real connection-retention defects; it did not establish the cause of the historical ENOBUFS incident. Short-cycle checks are not a substitute for the still-outstanding 24–48-hour continuous-operation soak. See the [investigation and evidence](../network-connection-lifecycle.md).

## Diagnostic process isolation

Optional diagnostic journal I/O now runs in a single private child process rather than a worker thread. Forced termination during native libSQL execution can abort an entire worker-thread host; the matching Neon panic was reproduced independently and through the recorder timeout path. A separate process contains that failure while retaining bounded shutdown, epoch/gap handling, private projections, and the existing journal format. It does not introduce a Runtime upgrade or remove persistence/recovery tests.

This contains the reproduced diagnostic-worker termination mechanism. It does not establish that every historical native abort had that cause or rule out other native-library failures.

## Content-page settings

Workspace Settings now uses content-area pages for General, People & permissions, Conversation presets, and Defaults & timeouts. Presets have dedicated create/edit pages. Conversation Settings similarly separates administration from session defaults, roles, model/effort overrides, timeouts, and collaboration guidance.

Current Conversation settings are revision-checked and private to the Relay store. Original creation settings remain an immutable reference. New sessions and replacements use current settings; resuming an existing session retains its launch configuration. Threads inherit their parent's settings without sharing sessions or changing their frozen public context.

Working-folder validation and preparation finish before publishing a new Conversation. Exact retries retain preparation state and cannot overwrite later folder edits. Sidebar filing remains separate from execution working folders. See [Conversation presets and settings](../conversation-presets.md).

## UUIDv7 resource IDs

New resource IDs use UUIDv7 within the existing typed-prefix plus 32-hex format. Existing IDs, saved links, and legacy Channel IDs remain accepted; this does not rewrite existing resources. UUID timestamps are public and must not be treated as secrets or as authoritative message order. Message sequences remain the ordering contract.

## Upgrade and compatibility

- Add private Relay migrations **0016_conversation_settings** (current Conversation settings and Workspace turn timeout) and **0017_creation_folder_preparation** (durable creation-folder preparation state). Keep the public database schema unchanged from v0.0.32.
- Stop the app and back up the complete product data directory before upgrading. Startup applies pending migrations with existing backup safeguards. Verify persisted Conversations, folders, settings, and agent bindings after reopening. Downgrading migrated data is unsupported; restore a complete stopped pre-upgrade backup instead.
- Advance local-control protocol to **25**. Use the matching packaged web/control clients and reload old browser tabs after upgrade.
- Add core dependency `uuid` at the lockfile-pinned version. Runtime remains pinned to `f0ffbfcc5f24e75174bff1919aa5cd41ce22d732`; no Runtime upgrade is included.
- Retain the known Runtime resume/PID-publication race and imperfect recovery/context reconstruction described in [v0.0.32](v0.0.32.md) and [v0.0.28](v0.0.28.md). The diagnostic-worker termination mechanism is contained as described above; other native Neon abort mechanisms have not been ruled out.

## Verification and publication

The connection changes received targeted code review and independent V&V, including real-HTTP cancellation/backpressure and production-proxy browser/transport scenarios. Current-main integration checks passed 24 focused tests, including 100 disconnect cycles per SSE route. Those results retain their recorded source targets; they do not replace the release metadata commit's required CI or exact-artifact acceptance.

During release preparation, macOS CI rejected a diagnostic sidecar while reopening a journal. A native libSQL probe reproduced deferred cleanup unlinking an already-open sidecar before descriptor validation. This release handles that race only when the descriptor is still a private regular file and the optional named path is genuinely absent; replacement paths, unsafe descriptors, and unlinked main databases remain rejected. The historical CI logs lack descriptor metadata, so their exact stat condition cannot be proven retrospectively. See [the correction and verification evidence](../verification/diagnostic-sidecar-reopen.md). No CI gate, safety test, dependency, or file mode is relaxed. The sidecar correction and diagnostic-process isolation address distinct reproduced mechanisms; neither claims to resolve all native-library failures.

Require successful release-PR, exact-commit main, and tag-workflow checks. Verify the exact uploaded tarball/checksum and source pins, then record clean-account installation, upgrade/persisted-data reopen, and a genuine Pi response before publishing the draft as latest. Controlled Pi smokes do not replace that acceptance. Individual crashed-tab lease expiry, full agent workflows, and the long connection soak remain outstanding unless separately recorded. Follow [releasing guidance](../releasing.md).

Publishing does not install the package or restart existing installations.
