# MinuChannels v0.0.26

Compared with **v0.0.25**, this release adds durable message threads with separate agent sessions. Reusable Conversation presets are a separate update and are not included.

## Side discussions without mixing histories

Use **Start thread** on a top-level message to create one durable side discussion. Its reply count reopens the same side panel. Thread messages, drafts and send retries stay separate from the main timeline. Nested threads and independently named sub-conversations are not supported.

Each agent has its own thread Runtime session. Opening the panel does not start agents; use its participant controls. A with-context session receives bounded public parent context captured through **first thread creation**, always retaining the root. The stored snapshot stays frozen across reopening, delayed agent startup and restart. Later parent or sibling messages are not automatically added; private Runtime transcripts and tool history are never cloned. An explicit **Fresh session** omits inherited background.

## Inherited permissions and scoped controls

Threads inherit current parent participants, lifecycle and working folders rather than introducing separate administration. They cannot widen membership, change working folders independently or reopen an archived parent. Parent archival freezes thread writes and prevents agent starts; archive only when managed parent/thread work is idle or stopped.

Thread Start, Stop and session controls are scoped to the selected discussion. Recovery preserves cancellation, retired-request fences and later queued-work continuity. New delayed responses for retired requests are rejected at authoritative storage commit; retries of an already-committed response remain safe.

Separate sessions are **not filesystem isolation**. Agents continue to share the configured project folder; no automatic Git branches or worktrees are created.

## Bring results back manually

Ask the thread agent for a summary, then manually copy and post it as an ordinary main-conversation message. Mention an agent if follow-up is needed. Nothing synchronizes automatically. Copy-message and reviewed Share-to-conversation actions remain follow-ups.

See [Conversation threads](../conversation-threads.md) for context bounds and behavior.

## Compatibility and upgrade

- Public Conversation migration **0010** adds thread relationships, a unique root mapping and frozen context storage. Existing parent conversations retain their messages and identity.
- Local-control protocol remains **24**. Runtime stays pinned to `86bd35ea846740f55e83038b3ff823d9ddd67e34`; dependencies and Pi integration configuration are unchanged.
- Use Node.js **22.13+** for normal/background-service operation. Foreground use on 22.5–22.12 requires `NODE_OPTIONS=--experimental-sqlite`.
- Preserve a complete stopped data-directory backup before upgrading, including both databases, profile and attachments. Startup snapshots pending migrations; downgrading already-migrated data is unsupported. Do not migrate a running installation manually.

This release does **not** claim to fix the previously disclosed intermittent native Neon `PendingException` database abort. Its root cause and production impact remain unresolved; green runs do not erase that limitation. Controlled Runtime tests also do not establish every live model/profile, native clipboard behavior or abrupt crash-mid-turn durability.
