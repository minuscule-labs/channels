# MinuChannels v0.0.32

This release adds lightweight Workspace folders for organizing Conversations and aligns the application's action controls.

## Organize Conversations without changing execution

Use Workspace actions to create folders, folder actions to rename them or create a Conversation inside them, and **Move** on a Conversation to file it or return it to **Unfiled**. The Workspace quick-create icon remains available; new Workspace-level drafts default to Unfiled.

Folders are flat, sort alphabetically and remain visible when empty. Collapse preferences are browser-local to the current human and Workspace. Direct navigation and successful moves reveal the selected Conversation. Collapsed folder headers aggregate active unread messages and mentions without marking them read or double-counting Workspace totals.

Folders are navigation, not Projects, shared context, permission boundaries or source directories. Existing owner/admin, Workspace and lifecycle restrictions apply. Snoozed and Settled/Archived Conversations retain their assignment; reopening returns them to their folder. Threads remain attached to their parent with their own messages, frozen context and agent sessions.

Folder selection stays independent of Presets and private creation settings. Filed creation validates its target before provisioning, and a conflicting same-ID retry cannot silently move existing work. Background reconciliation fences stale responses while retaining stable event subscriptions.

## Compact navigation and action controls

Keep one selected Workspace and the existing selector. Folder rows have left chevrons, indented Conversations and vertical action menus. The active Conversation is highlighted, not its folder. Primary navigation/action text uses the existing 14px size.

The approved icon-only action controls use aligned borderless 36px targets and consistent hover/focus styling across the sidebar, participant/session/message menus, participant panel, thread header and Add Workspace. No new UI framework or dependency migration is included.

## Upgrade and compatibility

- Add public migration **0011_conversation_folders**. Existing top-level Conversations become Unfiled; IDs, messages, rosters, read cursors and private Runtime bindings are preserved.
- Stop MinuChannels and back up the complete product data directory before upgrading. Startup applies the additive migration with the existing backup safeguards. Downgrading migrated data is unsupported; restore a complete stopped pre-upgrade backup instead.
- Keep the private Relay schema, local-control protocol **24**, existing dependencies and Runtime pin `f0ffbfcc5f24e75174bff1919aa5cd41ce22d732` unchanged from v0.0.31.
- Retain the known Runtime resume/PID-publication race: a valid replacement worker can be rejected during resume because the old PID is observed before the new launch PID is published. This existing issue is outside the folder change and remains unfixed.
- Retain the recovery/context-reconstruction and intermittent native Neon database-abort limitations documented in [v0.0.28](v0.0.28.md). No fix for those limitations is claimed.
- Nested folders, folder deletion, drag-and-drop, bulk filing, shared agent context and shadcn/ui adoption are not included.
