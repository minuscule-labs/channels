# MinuChannels v0.0.46

Codex agents follow their current skills after you select every skill again, and stopping a stuck Pi agent on macOS no longer fails.

## Codex skills

- Selecting every skill again on an existing Codex agent removes its saved skill list. Codex then uses its own current skills, as a new Codex agent already does since v0.0.44, so a plugin update cannot leave that agent with a stale list.
- Agents saved earlier with every skill selected keep their list until a skill is unticked and ticked again.
- The local-control API accepts `skillIds: null` on agent configuration to remove a saved list.

## Pi agents on macOS

Stopping or restarting an unresponsive Pi agent no longer occasionally fails with `kill EPERM`. macOS can briefly report that error while the agent's worker is exiting. Runtime now keeps waiting until the exit is proven, and still never signals a worker it cannot inspect.

## Release checks

Every pull request, main build and release package is now installed and run with the real pinned Pi program against a local stand-in model: replies, selected skills, Stop and Start, restart and new conversations with a deleted skill, reopening data and clean shutdown. No login or network model is used. This does not replace a genuine Pi response through a real provider.

## Known limitations

- A Codex plugin skill that loads unusually late can stay on when only some skills are selected.
- A Codex plugin skill saved by v0.0.43 or earlier may show as not found until it is selected again.
- Codex and Claude Code agents still refuse to start when a selected skill is missing; Pi starts without it.

## Upgrade and release gates

There are no database migrations or dependency lock changes since v0.0.45. Local-control protocol stays at version 25; the new `skillIds: null` value needs this release's server. Back up the complete stopped data directory first, and reload browser tabs after updating. Updating from v0.0.43 or earlier also brings in the [v0.0.44 changes and known limitations](v0.0.44.md).

Runtime is pinned to `8239db90896b5ffdff1150bf781d4fb62e90fade`.
