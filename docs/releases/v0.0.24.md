# MinuChannels v0.0.24

Compared with **v0.0.23**, this release adds explicit recovery for stuck managed sessions and simplifies everyday controls.

## Agent controls without Runtime terminology

Participant menus stay compact with three groups: **Agent**, **New session**, and **Inspect**.

- **Stop agent** stops delivery and shuts down the exact managed worker, preserving its transcript.
- **Restart agent** shuts down the worker and reopens that same saved transcript; it does not create a fresh session or apply saved future launch settings.
- **Cancel current** interrupts only the current task.
- New-session replacement remains separate, with with-context and fresh choices and their existing confirmations.
- Inspect stays available while lifecycle actions are pending. Menus support keyboard/touch navigation, collision-safe flyouts and red stop actions.

Where managed shutdown is unavailable, the older delivery-only action is called **Pause agent** rather than being displayed alongside the full Stop action. Bulk lifecycle behavior is unchanged.

## Recovery when status is uncertain

Stop and Restart remain available for exact owner-scoped managed bindings even when ordinary status checks cannot verify a worker. Recovery fences delivery before shutdown and confirms process exit before resuming. The managed ID, binding generation, transcript and activation/context policy are preserved. A persistent Runtime fence prevents a delayed automatic wake from undoing a manual stop.

Unconfirmed shutdown stays fenced and never authorizes a second worker. New POSIX workers use dedicated process groups with exact worker/owner verification before TERM/KILL escalation. Legacy workers receive only targeted TERM and require verifiable exit evidence; unverifiable descendants remain unconfirmed. Tool or filesystem side effects cannot be rolled back. Automatic recovery-policy changes are not included.

Runtime also retains startup extension errors in its existing bounded private diagnostic log. This is not a claim to fix the separate native database/crash investigations.

## Settings and links

- Notification sound preferences move out of the sidebar into a dedicated **Notifications** section in Workspace Settings. Their existing per-browser, per-identity persistence and playback behavior are unchanged, including availability to non-admin members.
- Message links are blue in both light and dark themes; sidebar navigation keeps its existing colors.

## Compatibility

Runtime is pinned to `86f81102db9ddacade58009d040a95253188992b`. Local-control protocol advances to **24**; no authoritative database migration is added. The web client adds the compatible Radix dropdown-menu primitive. Pi integration configuration remains inherited from Pi, not managed by Channels. Node.js **22.13+** remains recommended; foreground use on 22.5–22.12 requires `NODE_OPTIONS=--experimental-sqlite`.

Existing workers are not replaced merely by publishing or installing the release. Some legacy/unverifiable workers cannot be forcibly recovered safely and remain fenced rather than receiving broad process-name kills.

Implementation verification includes **68 Runtime tests**, **339 backend tests**, and **180 web unit tests**, plus browser tests for recovery intent, confirmations, pending/read-only guards, keyboard/touch flyouts, settings persistence and theme-aware link colors. Both implementation PRs passed Ubuntu/macOS, browser and package CI. The latest grouped-menu source passed 116 affected browser cases locally and the full browser CI suite.

## Install or upgrade after publication

Download `minu-channels-0.0.24.tgz` and `SHA256SUMS`, verify the checksum and follow the [local installation/upgrade guidance](../local-release.md). Preserve a complete stopped data-directory backup before upgrading.

**Publication does not install, update or restart existing applications, change credentials, or alter existing agents.**
