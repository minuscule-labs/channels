# MinuChannels v0.0.16

Compared with **v0.0.15**, this update adds private, read-only message-delivery diagnostics so an owner or admin can distinguish agent execution from delivery of its reply.

## Follow a message through delivery

Open an agent's **Details & diagnostics → Message delivery**, then choose **Show** or **Refresh** to inspect recorded message trails.

A trail distinguishes observations such as:

- An eligible message being observed and processing starting.
- A new Runtime dispatch versus reuse of an existing turn.
- Runtime acceptance and its actual result, where supported.
- A public reply or terminal notice being committed, or acknowledgment of an existing response.
- Private recovery-cursor progress and uncertain or failed delivery outcomes.

Runtime completion is not treated as proof that a reply reached the Conversation. Missing evidence remains **Not recorded** or unknown; the inspector does not reconstruct history from timestamps, cursors or saved transcripts.

This is an advanced troubleshooting view. Everyday chat, participant badges, existing notices and agent lifecycle controls are unchanged.

## Bounded, private and read-only

- Keep up to **seven days or 1,000 completed message trails installation-wide**, whichever limit is reached first. Trails have separate retention and recording capacity so they cannot evict lifecycle-operation history.
- Capture fixed milestones rather than continuous output. Bound active records, event counts, snapshot bytes, read pages and deadlines; disclose clipping and recording gaps.
- Require an active human owner/admin and the exact current Conversation participant/binding/session scope. Revalidate authorization and ownership before delivering results.
- Inspect only on explicit Show/Refresh. Closing, navigation, observed replacement or access loss clears and fences the disposable view.
- Do not record or expose prompts, message/response bodies, raw errors, tool output, credentials, private paths or native session identifiers. Trails are not added to report exports, clipboard actions, browser storage or cross-tab caches.
- Inspection does not start, wake, resume, retry or recover an agent. Capture begins only when Relay actually observes eligible work; messages processed before capture or while detached may have no recorded trail.

## Storage and compatibility

Local-control protocol advances to **22**. The optional private diagnostic companion journal upgrades from schema **1 to 2**, preserving lifecycle records and adding the separate message-trail collection.

No public Conversation or authoritative Relay database migration is added. Runtime remains pinned to `e92176054206d70e120d4b6641bda2a3d037eb84`; Start, Stop, replacement and recovery semantics are unchanged.

Older application versions cannot read the newer optional diagnostic journal schema. Back up the stopped data directory before upgrading; this release does not promise an automatic downgrade or rollback. Logical retention/deletion is not secure erasure of SQLite pages, WAL files or backups.

## Verification and known limitations

The implementation merged in [Channels PR #46](https://github.com/minuscule-labs/channels/pull/46) after Ubuntu/macOS verification, full Chromium regression and release-package CI passed. Author checks include actual daemon/HTTP/temporary SQLite/native diagnostic-worker integration with controlled fake runtimes, and clean-package install/reopen checks. See [structured implementation evidence](../verification/message-delivery-diagnostics-author.json).

Versioned release preparation and publication use the same required CI, immutable Runtime pin, clean-source packaging, checksums and packaged-install smoke gates. These automated checks are separate from real-agent and external installed-artifact acceptance.

- Fresh genuine-Pi and clean-account macOS/Linux acceptance remain outstanding, as in v0.0.15. Publication does not claim that sign-off; real-agent runs require separate scoped approval.
- The earlier intermittent native database-related crash still has no proven root cause. This release does not claim to fix it.
- MinuChannels remains a single-user, loopback-only local alpha for macOS and Linux. Do not expose its ports to other machines or untrusted local users.
- **Image support is not included.** Uncommitted image work remains separate. Raw-log downloads, transcript exports, hosted storage, session branching and automatic recovery are also excluded.

## Installing or upgrading

Download `minu-channels-0.0.16.tgz` and `SHA256SUMS` from the approved GitHub Release and verify the checksum before installing:

```bash
npm install -g ./minu-channels-0.0.16.tgz
```

Follow [installation and upgrade guidance](https://github.com/minuscule-labs/channels/blob/v0.0.16/docs/local-release.md) to coordinate an existing instance and back up its data. Publishing this release does not upgrade or restart any installation.
