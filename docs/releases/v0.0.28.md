# MinuChannels v0.0.28

This release combines mainline agent recovery with the read protections from the emergency `0.0.27-recovery.0` build. It does not reset Conversations or delete saved agent transcripts.

For users upgrading from the last published **v0.0.26**, it also includes the recipient-selection, Send-triggered startup, thread-panel and API recipient changes documented in [v0.0.27](v0.0.27.md). The existing v0.0.27 tag and draft are not replaced or reused.

## Recover the agent, keep the Conversation

- Status and recovery target one owner-scoped saved session instead of validating every transcript in the installation.
- **Restart agent** prefers the original transcript. If that resume fails, it may open a replacement session in the same Conversation using bounded permitted public context and current configured launch settings.
- Recovery confirms that the old worker has stopped, including a worker launched by a late resume, before replacement. If shutdown cannot be verified, delivery stays fenced.
- The original transcript and private session-history record are retained. A recovery lease excludes competing lifecycle actions, and replacement commits its captured message boundary atomically so old commands are not replayed.
- Ordinary **Start** and background startup/lease recovery still only resume an existing saved session; they do not automatically create a replacement.

Full-transcript resume and inventory validation is limited to four readers per Runtime module and one per transcript path. Timed-out supported reads cancel queued work and stop between chunks. Already-issued OS reads retain their slots until their handles close. Routine exact status checks remain metadata-only.

## Upgrading from the emergency recovery build

The older updater in `0.0.27-recovery.0` rejects its own prerelease version. After this release is approved and published:

1. Download `minu-channels-0.0.28.tgz` and `SHA256SUMS`, and verify the checksum.
2. Let active work settle, stop MinuChannels, and back up the existing product data.
3. Install the verified tarball using the [manual upgrade path](../local-release.md#later-upgrades), then start the app.
4. Verify the existing Conversations, agents and configuration before removing the backup.

Keep existing product data and Runtime resume material in place. Do not reset the profile, remove lock databases, or edit installed bundles to perform this upgrade. Installation/recovery remains separate from release publication.

## Compatibility and known limitations

- Runtime is pinned to `f0ffbfcc5f24e75174bff1919aa5cd41ce22d732`, including merged Runtime PRs [#20](https://github.com/minuscule-labs/runtime/pull/20) and [#21](https://github.com/minuscule-labs/runtime/pull/21).
- Local-control protocol remains **24**. No new database migration or dependency is added relative to v0.0.26/v0.0.27.
- Use Node.js **22.13+** for normal/background-service operation. Foreground use on 22.5–22.12 requires `NODE_OPTIONS=--experimental-sqlite`.
- Private working memory may be lost during replacement. Consecutive fallback replacements of an originally Fresh session can progressively narrow recovered public context. This is an accepted first-version limitation; Conversation messages and retained transcripts are not deleted.
- Recovery does not roll back tool/filesystem side effects, reconstruct previously destroyed manifests, automatically synchronize later parent/sibling thread history, or add an installation-wide all-off hard restart.
- The previously disclosed intermittent native Neon `PendingException` database abort remains without a proven root-cause fix. Green CI does not erase that limitation.

See [Participant recovery](../participant-recovery.md) for recovery semantics and [local installation guidance](../local-release.md) for data and upgrade safeguards.
