# MinuChannels v0.0.41

Activity brings mentions and participated-thread replies into one inbox, with durable human unread state. This release also includes Codex in the existing per-agent Runtime setup.

## Activity and unread state

- See incoming direct mentions, channel broadcasts and replies in threads where you authored the root or had already participated. Own messages are excluded; later participation does not retroactively notify on earlier unmentioned replies.
- Open contextual previews at the exact Conversation/thread and its first unread message. Activity uses bounded, 50-item pages; the navigation badge counts all unread notifications, including unloaded pages. A mentioned reply counts once, ordinary unread messages do not inflate the badge, and zero is hidden on desktop and mobile.
- Keep human read state on the server across tabs, browser sessions and application restarts. Unread totals cover persisted messages, not only the browser's latest 100-message window. Existing valid browser read marks migrate monotonically and never rewind server state.
- Acknowledge only a focused, visible, unoccluded timeline at its end. Parent Conversations and threads have independent read scopes. Browsing Activity, snoozing/settling or unsubscribing does not mark messages read.
- Retry a failed read acknowledgement after successful stream or polling reconciliation, even without a new message or focus event. Keep parent Activity hashes out of nested thread views and avoid stealing composer focus on later live updates.

Activity is projected from persisted messages and current membership/roster access, not a separate notification queue. Access revocation is reflected on the next authorized refresh. A dedicated Threads screen, following controls, grouping, reactions and additional filters are not included.

## Bounded background delivery

Body-free inbox hints travel over the existing principal-scoped SharedWorker/SSE connection. They consume no Conversation slots and do not subscribe to every remembered Conversation; the 100-topic policy remains in place. An interested tab can retain an inbox-only stream with zero Conversation topics, and closing all consumers closes it.

Initial load, readiness, focus, reconnect and periodic snapshots reconcile authoritative Activity/unread state. Unsupported workers use polling. Hints are an optimization; persisted messages and read cursors remain the source of truth. See [Activity and unread state](../activity-inbox.md).

## Per-agent Codex setup

Choose `codex` through the existing agent detail page's **Private launch profile → Runtime → Harness** field. Pi remains the default; there is no installation-wide or per-Conversation harness selector. Saving a different adapter changes future-session configuration without replacing an existing live Pi binding. Change a running agent through the existing explicit new-session operation.

Codex must be installed and authenticated in the actual Channels service environment. Configured models, tools, hooks and integrations may execute when you start sessions or send messages. Interactive approval/answer handling and explicit recovery remain unfinished; cold suspend/resume/destroy eligibility is still macOS/v5-limited. See [Codex integration](../codex-agent-integration.md) for setup and limitations.

The package includes separate Pi and Codex worker resources. Controller restoration authenticates an already-living Codex worker before recovering status/turn delivery; it does not silently launch, cold-resume or repair it. Runtime is pinned to `52160fd8d875b6f9ab42684feceeeb1d1984db32`.

## Upgrade and release gates

Public migration `0014_human_read_cursors` adds human read cursors and a chronological message index. Existing messages, IDs, agent processing cursors and Runtime sleep/dispatch behavior are preserved. The local-control protocol is unchanged.

Back up the complete data directory before updating. Startup creates the normal pre-migration database snapshots; retain them until you have verified the updated installation. Downgrading an already-migrated directory is unsupported—restore the complete pre-upgrade backup instead. Reload browser tabs after updating to load the new assets and worker.

Linux and macOS CI now prepare the pinned sibling Runtime before testing Channels and report independently instead of cancelling one platform after the other fails. Before publication, require green ready-for-review PR, exact post-merge and tag-workflow checks, checksum/source-pin verification, and exact uploaded-artifact isolated installation, persisted reopen and genuine-Pi acceptance under [release guidance](../releasing.md).

Publishing does not install the update or restart an existing installation. No artifact acceptance or publication is implied by preparing these notes.
