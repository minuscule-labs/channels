# MinuChannels v0.0.34

This release simplifies Settings and introduces Workspace-authored Instructions and Skills with atomic Save and preserved session snapshots. These notes describe the prepared source candidate, not a published or artifact-accepted release.

## Simpler Settings

Workspace Settings provides dedicated pages for Agents, Instructions, Skills and Conversation presets, with consistent desktop/mobile navigation and compact Agents/Skills tables. Skills use separate New/Edit pages. People navigation is hidden; permissions and backend authorization are not removed.

Conversation settings contains name, normal participant selection and working folders. The separate Instructions/Skills, Participants & roles, Session defaults and Collaboration editors are removed. Existing channel-authored documents and non-timeout advanced Conversation settings remain operational underneath; removing an editor does not erase old guidance or silently change existing sessions.

Presets contain name, selected participants and task-specific Instructions. Their instructions are copied when a Conversation is created; editing a preset later does not update existing Conversations. Preset management stays in Workspace Settings, with confirmed, revision-checked removal.

## Instructions, Skills and session boundaries

One Save atomically updates an authored document and its immutable publication snapshot. Preview, archive, conflict checks and local-draft preservation remain; revision/history controls are not shown in Settings. Workspace Instructions form shared guidance, while preset-derived instructions remain separate task context.

New sessions capture current published guidance and skill references. Reconnecting, resuming, idle wake and recovery retain the original session manifest. A supported valid session without the selected skill revision is Pending rather than broken or unsupported; start a New session to capture it. There is no silent hot-update of running sessions, and guidance does not grant additional permissions.

The explicit `/skills` catalog, picker and guarded invocation infrastructure are included, but **production Skill invocation publication remains default-off**. There is no new CLI, environment or persisted enablement switch, and this release preparation does not enable an installation. Unsupported Harness invocation remains disabled. Pending/Ready describes session eligibility; a disabled publication gate still prevents submission. See [authored guidance and invocation boundaries](../authored-content.md).

Management checks current owner/admin authority after private reads, immediately before write dispatch and before returning private results. A write already dispatched while authorized may commit during later revocation; a subsequent 403 withholds its private response, not a rollback guarantee. An authorized reader must inspect uncertain outcomes rather than blindly retrying.

## Workspace-only turn limits

Workspace turn limits offer **30 minutes, 1 hour and 2 hours**, defaulting to **1 hour**. Conversations no longer override that policy. Already-running turns retain their snapshotted policy, and explicitly saved Workspace limits are not silently replaced.

Idle sleep remains a separate Workspace resource policy. Short internal network/runtime safety waits remain bounded separately. No Runtime upgrade or promise of removing every provider/runtime limit is included.

## Upgrade and data effects

Startup applies the following pending migrations through the normal protected upgrade path:

- Private Relay **0018_authored_documents** adds document heads and immutable publications; **0019_authored_session_context** adds nullable session manifests, distinguishing known-empty from legacy sessions without evidence.
- Private Relay **0020_authored_skill_invocations** and **0021_authored_invocation_message_links** add accepted-operation and publication-link records. Core **0012_authored_invocation_messages** adds a nullable public correlation field, not private procedure text. Existing messages and IDs are not rewritten.
- Private Relay **0022_minimal_presets** intentionally removes reusable-preset model/effort/timeout overrides, participant roles and unassigned role slots. It advances affected revisions. Existing Conversation creation snapshots and saved Conversation settings are not rewritten by this preset migration.
- Private Relay **0023_workspace_only_timeouts** removes editable Conversation turn/idle timeout overrides and advances affected revisions to reject stale writes. Immutable creation/session snapshots and explicitly saved Workspace policies remain unchanged.

Before upgrading, stop the app and back up the complete product data directory, including attachment bytes and Runtime/session material. Startup's consistent database/image snapshots supplement that backup. Do not run migrations manually against live data. Reopen and verify Conversations, messages, folders, agents and guidance before removing backups. Downgrading migrated data is unsupported; restore a complete compatible pre-upgrade backup instead. See [installation and upgrade guidance](../local-release.md).

Local-control protocol remains **25**; use matching packaged web/control assets and reload old browser tabs after upgrade. Runtime remains pinned to **f0ffbfcc5f24e75174bff1919aa5cd41ce22d732**. Existing UUIDv7 generation and acceptance of older IDs remain unchanged from v0.0.33.

## Verification and publication gates

The rebased implementation passed the full 742-case backend/storage suite, web types, 35 focused web tests and four focused browser scenarios. The upstream UUIDv7 draft test needed one Settings-to-Workspace navigation adjustment; its affected rerun passed with all ID/retry assertions retained. The three prior delegated findings received independent scoped closure before rebase; exact source-preservation checks show those fixes unchanged. These are source-checkout results, not release-artifact acceptance or final metadata-commit CI.

Required ready-for-review PR CI, successful post-merge main CI for the exact release commit, and the tag workflow must pass. The tag workflow prepares a draft artifact. Verify that exact uploaded tarball/checksum and source pins, then record clean-account installation, persisted-data reopen and a genuine Pi response before publishing it as latest. Controlled/fake-Pi checks do not replace acceptance. Follow [release guidance](../releasing.md).

The known Runtime resume/PID-publication and recovery/context-reconstruction limitations, other possible native-library failures, and uncompleted connection soak remain disclosed in [v0.0.33](v0.0.33.md). Explicit Skill invocation activation is a separate, unapproved action. The product remains a single-user, loopback-only local alpha; do not expose it to an untrusted machine or local user.

Publishing does not install the package or restart existing installations.
