# MinuChannels v0.0.19

Compared with **v0.0.18**, this release improves participant recovery and separates everyday controls from privileged diagnostics. It does not change database schemas or the pinned Runtime.

## Reliable participant actions

- Track each exact Start, Fresh session, New session with context, Reconnect, Stop or Cancel request independently of browser deadlines and current Runtime activity. Late completion no longer becomes a false failure merely because the original browser request stopped waiting.
- Reconcile uncertain requests through read-only receipt queries. Never automatically repeat a mutation after transport loss; deduplicate retained request IDs and reject overlapping individual, bulk and legacy requests rather than queueing duplicate replacements.
- Keep confirmed outcomes stable when a delayed acceptance response or failure arrives. Superseded requests cannot resurrect old feedback; authorization denial still clears browser control ownership.
- Keep other participants usable while one participant is changing. Genuine Conversation lifecycle transitions and bulk actions retain their broader admission guards.

Receipts are bounded, in-process observations, not a durable job queue. Restarted, expired or missing receipts remain unconfirmed, not proof of failure or permission for automatic replay.

## Everyday recovery controls

Each participant menu offers read-only **Refresh status**, including when ordinary session actions are unavailable. Individual refresh can recover additional participants even if the collection status request keeps failing. Action notices are dismissible from expanded rows, compact details and minimized menus without deleting history or unlocking pending operations.

An explicit Stop retry can reuse the same durable stopping fence and verify or interrupt the same Runtime session without changing generation or automatically resuming or replacing it. Fresh-session context exclusion is preserved: Fresh start on an already stopped session is rejected; explicit Fresh replacement creates a new session.

## Separate diagnostics

Privileged diagnostics now has its own lazy-loaded participant page. Open it from the participant menu or in a separate tab from compact Details. The page retains owner/admin authorization, exact issue and public-message navigation, disposable private reports, and read-only inspection during pending actions.

Observed authorization denial clears the entire page even when public membership metadata is stale. Reports are not shared between tabs or saved in browser storage. Loaded public-message navigation remains usable beyond the sidebar's bounded message preview.

## Compatibility and limitations

- Local-control protocol advances from **22 to 23**. Run the bundled browser and host from the same release; reload an already-open browser after upgrading.
- No authoritative or diagnostic database migration is added. Runtime remains pinned to `e33b8a2da639832947b1bb203b45be5cc40d0772`.
- Node.js requirements remain **22.5+ with SQLite enabled**; **22.13+** is recommended for flag-free operation and the macOS background service. Foreground operation on 22.5–22.12 requires `NODE_OPTIONS=--experimental-sqlite`.
- The reviewed menu transport latch may keep eligible session controls disabled for up to the three-second acceptance timeout after an exact receipt confirms completion. This is a bounded, non-blocking limitation, not a replay or false operation outcome.
- Native-addon crash investigation [#51](https://github.com/minuscule-labs/channels/issues/51) and lifecycle test-fixture timing issue [#52](https://github.com/minuscule-labs/channels/issues/52) remain separate and are not claimed fixed.

## Verification and release status

The independent contextual review approved the recovery implementation with the bounded menu-lock limitation above. Author verification and the preceding finding-driven regressions are recorded in [participant recovery verification](../verification/participant-recovery-author.json). Review approval is not release acceptance.

Release preparation must still pass PR checks, post-merge checks and the tag workflow. Keep the generated release as a draft until its exact uploaded tarball and source pins are verified and a clean-account installed artifact passes persisted reopen and a genuine Pi response. Source tests, controlled Pi RPC checks and locally generated packages do not establish that acceptance. No installed app or live participant is updated by release preparation or publication.

## Install or upgrade after publication

Download `minu-channels-0.0.19.tgz` and `SHA256SUMS` from the approved release, verify the checksum, then install using the [local installation and upgrade guidance](../local-release.md). Back up and preserve the complete stopped data directory, including databases, profile and attachment files. Downgrading migrated data remains unsupported.
