# MinuChannels v0.0.43

Codex agents can now be set up alongside Pi and Claude Code, with the same access level, the full skill list and clear setup messages.

## Before you update: Codex access changes

New Codex sessions run with the `danger-full-access` sandbox and approvals off. **A Codex agent can change anything your account can, without asking**, as Pi and Claude Code agents already can. v0.0.41 and v0.0.42 used `workspace-write`.

Existing Codex sessions keep the sandbox they were created with and are never widened on resume. An earlier Channels release may not be able to read sessions created with the new sandbox.

## Codex setup and skills

- Codex plugin skills such as `pdf:pdf` no longer make all Codex model and skill discovery fail.
- Agent setup waits for Codex to finish loading plugin skills before listing them, so Codex discovery, and starting a session with selected skills, takes at least about 0.6 seconds longer.
- The Skills tab no longer says that no skills were discovered when discovery failed.
- Setup shows fixed instructions when Codex or Claude Code is not installed, Codex is not signed in, or the Claude Code version is unsupported. Native error text is never displayed.
- An image sent as the first message to a Codex agent is accepted when its model supports images.

## Empty replies

An agent that finishes its work without writing a reply now posts "Finished without a written reply." This used to be reported as a failed turn with a suggestion to retry. It applies to every harness.

## Claude Code

Claude Code history tolerates unknown bookkeeping rows instead of refusing the session.

## Known limitations

- Codex does not report its connected tools, so a running session's Integrations section shows Unsupported. Codex also reports a running session's skills as not verified.
- A missing or signed-out Codex can surface at discovery or the first turn rather than when the session is created.
- Codex cold suspend, resume and destroy eligibility is still limited to macOS.
- A Codex skill that takes unusually long to load can still be missing from setup.

## Upgrade and release gates

There are no database migrations, dependency lock changes or local-control protocol changes since v0.0.42. Upgrading from v0.0.41 also applies the v0.0.42 migrations; see [v0.0.42](v0.0.42.md) and back up the complete stopped data directory first.
