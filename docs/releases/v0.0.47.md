# MinuChannels v0.0.47

Authorized local clients can inspect who is present and which agents are running in explicitly granted Conversations and threads.

## Scoped status API

`POST /api/agent/v1/conversation/inspect` accepts a bearer key and one known Conversation or thread ID. It returns the complete permitted participant roster and explicit agent states. Generic keys name their permitted targets; locked keys name one target. Including existing and future threads is an explicit grant.

An active human Workspace owner/admin provisions and manages their own delegated keys through the existing authenticated human session. Keys have one-time secret delivery, revision-checked updates, expiry, immediate rotation and revocation. Current principal authority and grants are checked again before a result is released, including changes made while an inspection is running.

Inspection is read-only. A failed agent probe is uncertain; an incomplete or oversized roster fails rather than silently truncating. The API does not start or recover agents, read messages, post reports, change recipients or mark anything read. Status does not establish task progress or completion.

See the [provisioning and credential guide](../agent-api-credentials.md) and [OpenAPI 3.1 specification](../openapi.json). There is no integrations UI, MCP server or hosted API in this release.

## Upgrade

Private Relay migration `0029_agent_credentials` adds credential persistence. Existing public messages, read cursors and Runtime bindings are preserved. Back up the complete stopped data directory before updating and reload browser tabs afterward.

Runtime remains pinned to `8239db90896b5ffdff1150bf781d4fb62e90fade`; local-control protocol remains 25 and dependency locks are unchanged. Source development may select a clean built pinned Runtime through `MINU_RUNTIME_ROOT`; packaged loading remains available.

## Known limitations and acceptance

- A historical local native storage shutdown crash remains an open follow-up. It did not recur in the accepted backend's Linux/macOS CI; its exact cause is unresolved.
- Current policy has no separate stored restricted-thread ACL. Acceptance covers the implemented Workspace/principal and explicit target-grant policy; a future ACL needs its own enforcement and verification.
- Existing Codex/Pi skill limitations from [v0.0.46](v0.0.46.md) remain applicable.

Required PR, post-merge and tag-workflow checks, checksum verification of the uploaded artifact, a clean-account installation, persisted-data reopen and a genuine Pi response remain release gates. Preparing these notes does not claim those later checks have passed. Publishing does not update or restart an installation.
