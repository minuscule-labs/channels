# MinuChannels v0.0.40

Critical browser live-update reliability fix: remembered Conversations no longer cause an oversized SSE subscription to retry indefinitely.

## Live-update policy

- Keep one principal-scoped SharedWorker/SSE connection across tabs, capped at 100 unique Conversation IDs. This is an application subscription limit, not an SSE protocol limit.
- Prioritize visible channels and open threads; each thread occupies a slot. Retain departed/hidden views for five minutes, without extending inactivity through worker heartbeats.
- Evict older inactive topics when a new view needs capacity. If all slots are foreground views, excess views use snapshot polling instead of opening another SSE connection.
- Suspend settled/snoozed Conversations and their threads when lifecycle state is known. Reopening reconciles missed messages before reporting live readiness.
- After successful lifecycle mutations, send principal-scoped, ID-only cross-tab notifications so peers refetch authoritative lifecycle state even while SSE is paused. Cap snooze recheck timers at one day and recompute remaining time, avoiding native timer overflow for long custom snoozes.
- Fall back to snapshots for unchanged permanent HTTP subscription rejections; retain unsupported-worker polling.

Remembered background history observes available events but no longer creates live subscriptions of its own. Background unread counts and notification sounds can be delayed or missed after subscription expiry/eviction. Messages remain persisted and are fetched on reopening; a lightweight workspace notification feed is future work.

## Compatibility and release gates

No backend, database migration, Runtime pin, dependency, or local-control protocol change from v0.0.39. Runtime remains `42be4b7a89bf10f38bb453bb9b29bb5edd6eb6b9`. Agent Runtime sleep, message persistence and read-cursor semantics are unchanged.

The reviewed implementation is ported onto published v0.0.39 without carrying unrelated unfinished checkout changes. Required ready-for-review PR, exact post-merge and tag checks, checksum/source-pin verification, and exact uploaded-artifact isolated installation/reopen/genuine-Pi acceptance precede publication under [release guidance](../releasing.md).

Publishing does not install the update or restart existing installations. Use the checksum-verified updater with a complete data-directory backup and active-work protections. Reload existing browser tabs after updating to load the new browser assets and worker.
