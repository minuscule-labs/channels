# MinuChannels v0.0.18

Compared with the latest stable **v0.0.16**, this release adds Conversation images and compatible-agent vision, and fixes the product data-directory lock race that kept **v0.0.17** on prerelease validation hold. The v0.0.17 tag and files remain unchanged.

## Safe product-directory ownership

A private `run/instance-lock.sqlite` now holds a SQLite writer transaction for the full product lifetime, including startup, stale-marker recovery and shutdown. Concurrent contenders cannot inspect and replace an old marker while another instance becomes its live owner. The OS releases the transaction if its process exits or is killed.

The lock database stays in place across normal reopen. Same-process initialization is guarded by the canonical directory path; symlinked, hardlinked, non-file and foreign-owner lock databases are refused, and the file is owner-only. Live legacy owner markers and recent unfinished markers remain protected. No authoritative database schema change is needed for this locking fix.

**Stop older installations before upgrading.** Old versions do not participate in the SQLite lock, so simultaneous mixed-version launches are unsupported. Never delete, replace or restore the lock database while a process may still hold it. Back up and restore the complete stopped data directory, including attachment files.

## Conversation images and agent vision

The image functionality from [v0.0.17](https://github.com/minuscule-labs/channels/blob/v0.0.18/docs/releases/v0.0.17.md) is included:

- Pick, paste or drop PNG, JPEG, GIF and WebP images into a Conversation, alone or with text. Limits are four images, 10 MiB each and 20 MiB combined.
- Preserve attachment order, durable local bytes, completed-upload retry payloads and duplicate prevention across reopen.
- Deliver bounded image parts to owned Pi sessions only when the active model verifies image support. Unsupported sessions keep explicit unavailable-image markers; no image paths or public URLs are passed to agents.
- Preserve image-aware turn identity, cancellation before dispatch, managed transcript resume and Fresh-session boundaries. Old turn finalizers cannot clear newer execution ownership.

Image bytes remain in owner-private local storage. Native Pi may retain image parts in private transcripts and send them to the configured provider. External Markdown images, public sharing, hosted storage, generic files and cross-machine synchronization remain out of scope. See [image support](https://github.com/minuscule-labs/channels/blob/v0.0.18/docs/image-support.md).

## Runtime requirements and compatibility

The packaged foreground app requires **Node.js 22.5+ with SQLite enabled**. Use **22.13+** for flag-free operation and the macOS background service; foreground operation on 22.5–22.12 requires `NODE_OPTIONS=--experimental-sqlite`. `doctor` now checks SQLite availability rather than only the Node major version.

Runtime remains pinned to `e33b8a2da639832947b1bb203b45be5cc40d0772`. Local-control protocol 22, optional diagnostic-journal schema 2 and the authoritative Relay schema are unchanged. Upgrading from v0.0.16 still includes Conversation attachment migration 0009; preserve the databases, profile and attachment bytes together. Downgrading migrated data is unsupported.

## Verification and release acceptance

The lock regression deterministically admits two holders against the old implementation and only one against the fix. Author checks passed 319 backend tests, including 14 lock tests, plus isolated packaged install/reopen/image/concurrent-launch checks on current Node and Node 22.5 with SQLite enabled. Cross-process tests include four contenders and SIGKILL recovery. See [lock verification](https://github.com/minuscule-labs/channels/blob/v0.0.18/docs/verification/data-directory-lock-recovery.json).

The tag workflow stages a draft. The producer must verify its exact uploaded tarball and source pins, install it in a clean account, reopen persisted data and receive a genuine Pi response before publishing it as latest. PR, post-merge and tag-workflow checks must all pass; draft acceptance results are recorded separately from the earlier working-tree checks.

The intermittent native Neon `PendingException` database abort remains without a proven root cause; this release does **not** claim to fix it. The separate Runtime startup PID-fixture timing failure is also not claimed fixed. Earlier failures remain disclosed even when later checks pass. Genuine-model compatibility is limited to the observed model; clean Linux container-account acceptance does not establish a clean macOS login-account or interactive manual-browser run.

## Install or upgrade

Download `minu-channels-0.0.18.tgz` and `SHA256SUMS` from the approved release, verify its checksum, then install:

```bash
npm install -g ./minu-channels-0.0.18.tgz
```

Follow [local installation and upgrade guidance](https://github.com/minuscule-labs/channels/blob/v0.0.18/docs/local-release.md). Publishing does not update or restart any existing installation.
