# MinuChannels v0.0.35

This patch enables the supported Skill-send flow that was implemented but default-disabled in v0.0.34. These notes describe the prepared candidate; publication remains gated on CI and exact installed Skill-send acceptance.

## Skill sending enabled in normal startup

Normal product and control-daemon startup now enable authored Skill publication without a hidden opt-in. An embedding host can still explicitly set `authoredSkillPublicationEnabled: false`; the lower-level service alone remains fail-closed without host enablement.

Save a Workspace Skill, use a supported agent session that captured that publication, select the Skill and intended agent recipients in the composer, then Send. A session missing that revision remains Pending until a new session captures it; existing sessions are not silently replaced or hot-updated. Unsupported Harness invocation remains unavailable.

Enabling publication changes availability, not authority. Existing authenticated actor, scope, recipient, exact session/revision pin, retirement, lifecycle/lease and private-body checks remain. Accepted intent is still separate from explicit publication: reopening an installation does not automatically publish parked operations. Inspect uncertain receipts rather than blindly resending. Retained publication acknowledgments refer to the original message and do not start another turn.

## Upgrade boundaries

- No new migration, dependency, local-control protocol or Runtime pin change. Runtime remains `f0ffbfcc5f24e75174bff1919aa5cd41ce22d732`; local-control protocol remains 25.
- v0.0.34 and its artifacts remain unchanged. The startup default takes effect only after installing this patch and starting the updated host; publishing alone does not upgrade or restart an installation.
- Use the normal checksum-verified updater, complete data-directory backup and active-turn protections. Verify the installed version, capability, appropriate session pins and actual Skill-send behavior. See [upgrade guidance](../local-release.md).
- This does not add tool permissions, credentials, external-service access or implicit agent starts. Existing provider/recovery/native-library limitations remain as documented in [v0.0.34](v0.0.34.md).

## Verification and acceptance

The bounded source change received independent approval. Compilation, 121 affected backend cases and 16 isolated Skills browser scenarios passed independently. A separate simulated-Runtime product probe starts a session through the ordinary authenticated action, reopens with the option omitted, and proves Ready, retained pins, no automatic publication of parked intent and exactly one explicit selected turn. Simulated results are not genuine installed Skill execution.

Before publication require the new commit's PR/main/tag/package checks and the exact uploaded artifact's isolated install, persisted reopen and genuine Pi Skill execution through normal default startup and the installed composer. Its expected marker must come from the private procedure, not an ordinary echo. The original restricted-Notes denied-create/no-fallback criterion also remains open until an approved restricted fixture and bounded attempt establish the required no-write/no-fallback outcome. Historical successful Notes tasks and old live approvals do not close or authorize that test.

Do not change existing credentials/grants, invent a denied destination, reuse the exhausted historical turn budget or silently substitute generic Pi acceptance for Skill sending. These are acceptance gates, not a request to redesign the guarded producer. Follow [release guidance](../releasing.md).
