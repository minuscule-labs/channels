# MinuChannels v0.0.23

Compared with **v0.0.22**, this patch lets Pi manage its own integrations instead of disabling them at the Runtime boundary.

## Pi configuration is the source of truth

- Runtime no longer passes `--no-extensions`. Pi's configured extensions, built-in integrations and MCP servers can load during capability discovery and newly launched/resumed workers.
- Configure integrations in Pi. Codemode is available when enabled by Pi's settings or normal integration behavior; Channels does not force it on.
- No additional checkboxes, per-agent integration selection or Channels-owned integration configuration is added. `pi-runtime.json` remains ignored and `--pi-config` remains unsupported.
- Existing Skills selection, inherited host environment, managed sessions, image input and diagnostics are unchanged.

## Trust and existing sessions

Extensions execute trusted code with the host's permissions and must work over headless RPC. MCP servers may start processes or connect to external services. Runtime already launches Pi with `--approve`; project-local configuration is therefore trusted for that process too. Disposable live review also follows Pi's configuration, so isolate Pi configuration when testing untrusted setups.

Required credentials must reach the actual service process. This patch does not provision credentials, grant API permissions or introduce an integration sandbox.

Installing or publishing this release does not change tools in already-live workers. Use a new agent session, or suspend/resume an idle managed worker under the updated Runtime, to load the configuration. Reconnect alone does not reload integrations.

## Compatibility

Runtime is pinned to `7bd8a689dec0776d0b1fd5642d1a97353c9b251b`. No database migration, package dependency change or local-control protocol change is included. Protocol remains **23**. Node.js **22.13+** is recommended; foreground use on 22.5–22.12 requires `NODE_OPTIONS=--experimental-sqlite`.

## Verification and release acceptance

Runtime typechecks and **62 Runtime tests** passed, including launch/resume integration-override assertions, selected/empty Skills and inherited synthetic credentials. These controlled-Pi tests do not establish compatibility with every extension or MCP server.

Release preparation also requires Channels typechecks, backend and web unit tests, a clean-source pinned-Runtime package and disposable installed-package smoke checks. Require release-PR, post-merge and tag-workflow checks before acceptance. Keep the GitHub release as a draft until its exact uploaded artifact and source pins are verified and a clean-account installed artifact passes persisted reopen and a genuine Pi response. Record acceptance separately before publishing as latest.

The pre-existing native database abort and service/startup-fixture investigations disclosed in v0.0.20 remain separate; this patch does not claim to fix them.

## Install or upgrade after publication

Download `minu-channels-0.0.23.tgz` and `SHA256SUMS` from the approved release, verify the checksum and follow the [local installation/upgrade guidance](../local-release.md). Preserve a complete stopped data-directory backup before upgrading.

**Publication does not update or restart installed applications, change credentials, or alter existing agents.**
