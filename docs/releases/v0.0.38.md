# MinuChannels v0.0.38

This release adds read-only, current-worker integration discovery to existing session diagnostics. Supporting workers report configured integrations, connection state, configuration source, registered/callable tools, exposure and bounded failure codes. Unknown, unavailable and unsupported observations do not establish that an integration is absent.

## Native worker prerequisite

Runtime is pinned to `42be4b7a89bf10f38bb453bb9b29bb5edd6eb6b9`. It reads an optional native `get_integrations` interface from the actual participant worker. Supporting Pi workers expose the same safe observation to agents through `inspect_integrations`, helping distinguish a broken convenience wrapper from another working connection.

The native implementation is currently a separately prepared local Pi patch against v1.4.0, artifact `1.4.0-minu.integrations.3`. It is **not bundled, published or installed by this release**. Full native/agent discovery requires an explicitly selected supporting worker. Without it, existing workers remain usable and inspection reports unsupported. This release does not make agent-side discovery universally available on unpatched Pi installations.

Worker executable selection remains `options.command`, then `PI_COMMAND`, then PATH `pi`. No global executable or integration configuration is changed. Distribution and production selection of the local native artifact require a separate approved delivery step.

## Boundaries

Inspection is owner/participant scoped, observes existing workers only and never starts/resumes them or calls business tools. Agent and Channels projections omit native session identity, raw configuration, endpoints, paths, credentials and raw errors. Bounded evidence preserves unknown counts and attributes normalized failures to their integration.

Refresh remains read-only. No integration reconnect, configuration reload, sign-in flow, credential editing or disabled-integration enablement is included. There is no database migration, dependency or local-control protocol change. Existing recovery/context-reconstruction and native-library caveats remain outside this work.

## Release and upgrade

This is release preparation, not publication or installed acceptance. Require successful ready-for-review PR checks, exact post-merge and tag CI, then checksum/source-pin verification and exact uploaded-artifact clean-account/reopen/genuine-Pi acceptance under [release guidance](../releasing.md) and [local acceptance guidance](../local-release.md#verification).

Validate discovery separately with a supporting worker; successful artifact startup on an unsupported worker is not discovery acceptance. Publishing does not update installations or replace existing agent workers.
