# MinuChannels v0.0.39

Shared playbooks now behave like message attachments rather than session-installed capabilities.

- New sent Skill messages show a name-only badge. Exact publication revision, source and document identity remain recorded; the badge denotes attachment, not agent completion.
- Shared playbooks follow ordinary routing: sticky and explicit recipients, human recipients, Channel-wide broadcasts and unaddressed messages. Normal wake policies apply, including `all_messages`, direct-mention and muted behavior. An empty recipient list is not silently expanded into all agents.
- The selected publication is captured at message acceptance. Newly created or updated shared Skills can be used by existing supported sessions, including manifest-free legacy sessions, without resetting agents or changing their standing instructions.

Unsupported agent-native entries remain hidden from the send picker. Agents can still use their enabled native skills when asked in ordinary messages. Agent-scoped native discovery/invocation is deferred.

## Safeguards and compatibility

Procedures remain private. Permission, retirement, immutable revision/hash, trusted private message linkage, stable-turn admission, lease/Stop fencing, duplicate-send and uncertain-publication checks remain. Historical accepted invocations retain their original explicit-target/session-pin semantics; the new behavior applies to newly accepted messages.

Two additive nullable database columns preserve sent-message metadata and ordinary recipient intent. Existing messages and sessions are not rewritten. Back up the full data directory before upgrading; restore the complete pre-upgrade backup rather than downgrading an already-migrated installation.

No Runtime pin, dependency or local-control protocol change from v0.0.38. Runtime remains `42be4b7a89bf10f38bb453bb9b29bb5edd6eb6b9`.

## Release and upgrade

Required PR, exact post-merge and tag CI, checksum/source-pin verification, isolated installed-artifact persisted reopen and genuine Pi response acceptance precede publication. Source checks and simulated browser responses do not replace exact-artifact acceptance. See [release guidance](../releasing.md).

Publishing does not install the update or restart existing installations. Use the checksum-verified updater with a complete data-directory backup and active-work protections.
