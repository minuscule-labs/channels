# MinuChannels v0.0.21

Compared with **v0.0.20**, this patch keeps chat text selectable and reduces unnecessary status requests.

## Stable selection and copying

Status refreshes previously recreated rendered Markdown elements, clearing text selections and making the chat feel as though it was constantly refreshing. Message renderers now retain stable component identities and skip reprocessing unchanged message bodies. Selected text survives status polls and incoming messages and remains copyable.

## Quieter polling

- Active Runtime status refreshes every **5 seconds**, rather than every second. Idle status remains at five seconds, with thirty-second error backoff.
- Action receipts refresh every **15 seconds when idle**, rather than every second, in chat and the participant diagnostics page. Pending actions retain one-second reconciliation; the diagnostics page backs off to thirty seconds on read errors.
- Chat receipt polling pauses while the document is hidden and refreshes immediately when visible again. Diagnostics queries retain their existing background-polling defaults.
- Live Conversation events, diagnostic permission checks, explicit refresh controls and mutation safeguards are unchanged. An action initiated in another tab can take up to fifteen seconds to appear in an idle view.

## Compatibility

No database migration, dependency, local-control protocol or Runtime pin changes are included. Protocol remains **23** and Runtime remains at `34f5b17239078d425d0df69766f159099bb848dc`.

Node.js **22.13+** is recommended; foreground use on 22.5–22.12 requires `NODE_OPTIONS=--experimental-sqlite`.

## Verification and release acceptance

Browser regression coverage checks persistent DOM identity, selected-text copying across status and message updates, adaptive receipt polling, hidden-tab pause/resume, and active-status request frequency. Existing participant recovery and diagnostics access-loss regressions remain required.

Require release-PR, post-merge and tag-workflow checks. Keep the release as a draft until its exact uploaded tarball, checksum and source pins are verified and a clean-account installed artifact passes persisted reopen and a genuine Pi response. Record that acceptance separately from source tests and controlled package smoke checks before publishing as latest.

The pre-existing native database abort and service/startup-fixture investigations disclosed in v0.0.20 remain separate; this patch does not claim to fix them.
