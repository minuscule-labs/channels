# MinuChannels v0.0.25

Compared with **v0.0.24**, this patch fixes valid Pi session journals being refused on resume and removes recovery paths that could replace or discard a saved session's managed resume mapping.

## Durable native Pi sessions

Runtime no longer keeps a closed copy of Pi's entry-type, message-role or payload schemas. Native context edits, usage entries and additional tree roots remain valid resume material as Pi evolves. Runtime still validates owner-private files, canonical working-directory/header identity, bounded journal reads, JSON and message envelopes, unique IDs and parent ancestry. It does not rewrite transcripts or bypass ownership checks.

The confirmed failure involved valid native `context_edit` records that Pi could load but the older Runtime validator rejected. This release fixes that compatibility blocker; it is not a claim that every possible worker, provider or filesystem error is resolved.

## Less recovery machinery

- Startup can reopen an existing exact-owner managed session, but no longer creates a replacement when resume fails. Managed identity, binding generation, context policy and pending-message cursor are preserved.
- Explicit **New session** remains separate. It now retires and suspends the previous owned session while retaining its resume manifest and history instead of discarding its managed mapping.
- Older queued automatic-destroy jobs become non-destructive suspend attempts. Missing or unavailable sessions are not falsely reported as successfully cleaned up.
- Resume failures retain bounded `session_metadata_unavailable`, `session_transcript_invalid` or `session_resume_failed` evidence. Raw errors, native identifiers, paths and transcript contents remain private.
- Existing action errors no longer recommend creating a new session as the ordinary recovery step.

Worker-exit confirmation, exact-owner checks, lifecycle serialization, delivery/generation fencing, explicit-stop resume fences and bounded lease/verification retries remain. No second worker is authorized by uncertain shutdown. Failure cleanup for a newly launched, never-bound session remains separate. Tool/filesystem side effects cannot be rolled back.

## Important limit for older sessions

This release does **not** automatically reconstruct manifests discarded by older releases or scan/reassign old orphaned transcripts. Some older journals may still exist even when history says their managed metadata was destroyed. Recovery of such a session must be explicit; publishing or installing this patch does not switch an agent back to an earlier session.

## Faster development feedback

Development guidance now selects affected files and test names rather than treating every edit as a full-suite checkpoint. The web test wrapper correctly forwards name filters. Browser coverage is consolidated from 135 to 127 cases and CI uses three isolated, single-worker shards with timing reports. Superseded PR runs cancel automatically; required integration and release gates remain unchanged.

## Compatibility

Runtime pin: `86bd35ea846740f55e83038b3ff823d9ddd67e34`, included in merged Runtime PR #19. Local-control protocol remains **24**; no authoritative database migration, dependency or UI framework change is added. Pi integration settings remain inherited from Pi.

Node.js **22.13+** is recommended; foreground use on 22.5–22.12 requires `NODE_OPTIONS=--experimental-sqlite`. Existing workers are not replaced merely by publication or installation. The separate native database/crash and service-fixture investigations are not claimed fixed.

## Verification and release acceptance

Implementation CI passed **70 Runtime tests**, **343 backend tests**, **180 web unit tests**, the browser suite and packaged install/reopen/image-delivery checks. An explicitly requested independent delegated review approved the combined changes with no actionable findings; its live-provider acceptance limitation remains a release gate rather than an implementation approval claim.

Require release-PR, post-merge and tag-workflow checks. Keep the release draft until its exact uploaded tarball/checksum/source pins are verified, a clean-account installed artifact reopens its persisted data and receives a genuine Pi response, and that acceptance is recorded separately. Source tests, read-only transcript validation and controlled/fake-Pi smoke do not replace real-provider acceptance.

## Install or upgrade after publication

Download `minu-channels-0.0.25.tgz` and `SHA256SUMS`, verify the checksum and follow the [installation/upgrade guidance](../local-release.md). Preserve a complete stopped data-directory backup before upgrading.

**Publication does not install, update or restart existing applications, change credentials, or alter existing agents.**
