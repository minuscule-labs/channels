# MinuChannels v0.0.22

Compared with **v0.0.21**, this patch removes the optional Pi extension-loading configuration introduced in v0.0.20. Existing authorized Skills → shell → HTTP/API workflows do not require native extensions.

## Removed extension configuration

- Channels no longer reads `pi-runtime.json` or supplies extension options to Runtime. Existing files are left in place, not deleted or migrated.
- Foreground and development/review launchers reject the removed `--pi-config` flag. Remove that flag from launch commands before using this version.
- Runtime no longer accepts the Pi-adapter `extensionPaths` option or forwards explicit extension paths to owned workers. Automatic extension discovery remains disabled.
- The selected Skills workflow, inherited environment behavior, owner-scoped managed sessions, image support and diagnostics remain available. Already-live workers are not changed by installing or publishing this release; their loaded tools remain until the worker is replaced or suspended/resumed under the new Runtime.

## API credentials are a separate concern

For an authorized API workflow, an agent can use an API skill and existing shell tools without a dedicated integration CLI, MCP server or extension. Required credentials must reach the actual host/service process. Selecting a Skill does not provide credentials, and variables exported in a terminal do not automatically reach a background service.

**This patch does not fix service credential provisioning**, add a secret manager, authorize automatic API fallback, or change MinuNotes access permissions. Those changes remain separate.

## Compatibility

Runtime is pinned to extension-removal commit `815f1fa3f9c73d573ce69d2c11142c70b3f40ffc`. Its production Pi/core source matches the pre-extension implementation at `e33b8a2da639832947b1bb203b45be5cc40d0772`; the removal commit also includes focused inherited-environment and skill-selection regression assertions.

No database migration, dependency change or local-control protocol change is included. Protocol remains **23**. Node.js **22.13+** is recommended; foreground use on 22.5–22.12 requires `NODE_OPTIONS=--experimental-sqlite`.

## Verification and release acceptance

Local checks passed: both repositories' typechecks, **62 Runtime tests**, **332 Channels backend tests**, and the cross-repository image/managed-session integration smoke. Launcher regression coverage checks default Runtime construction, inherited synthetic API credentials, all four live launch modes, obsolete-file preservation and retired-flag rejection. Runtime assertions cover inherited synthetic credentials through startup/resume and selected/empty skill modes while keeping automatic extensions disabled.

Require release-PR, post-merge and tag-workflow checks. Keep the release as a draft until the exact uploaded tarball, checksum and source pins are verified and a clean-account installed artifact passes persisted reopen and a genuine Pi response. Record that acceptance separately before publishing as latest.

The pre-existing native database abort and service/startup-fixture investigations disclosed in v0.0.20 remain separate; this patch does not claim to fix them.

## Install or upgrade after publication

Download `minu-channels-0.0.22.tgz` and `SHA256SUMS` from the approved release, verify the checksum and follow the [local installation/upgrade guidance](../local-release.md). Preserve a complete stopped data-directory backup before upgrading.

**Publication does not update or restart installed applications, change credentials, or alter existing agents.**
