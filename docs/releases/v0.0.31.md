# MinuChannels v0.0.31

This release adds reusable, editable Conversation creation presets that reference existing Workspace agents.

## Review a preset before creating

Open **Create Conversation** and choose a saved preset or an **Exploration**, **Feature delivery**, or **Incident / debug** starting point. Assign agents to roles, adjust optional model/effort defaults and collaboration guidance, and review the draft before creating. Saving a preset does not create a Conversation or an agent.

Workspace owners and admins can save, update and delete presets. Each Conversation retains an independent creation snapshot, visible under **Settings → Creation settings**. Later preset edits or deletion do not alter that snapshot. Exact save/create retries recover lost responses; stale edits are rejected, and late editor requests cannot replace a newly selected draft.

## Agent settings and threads

Conversation defaults apply to initial and replacement sessions, including separate thread sessions that inherit their parent's creation snapshot. Threads retain their own messages and frozen public context. Resuming an existing session retains its launch settings. Workspace agent configuration and unrelated Conversations keep their own settings.

Unspecified model/effort fields use each referenced agent's configuration. Explicit Conversation overrides are validated. Disabled-model readiness for existing agents remains separate lifecycle work. Milestone check-ins are agent guidance, not scheduled reminders.

## Upgrade and compatibility

- Add private Relay migration **0015_conversation_presets** for saved presets and immutable creation snapshots. The public Conversation schema is unchanged.
- Before upgrading, stop MinuChannels and back up the complete product data directory. Downgrading migrated data is unsupported.
- Keep Runtime pinned to `f0ffbfcc5f24e75174bff1919aa5cd41ce22d732`, local-control protocol **24**, and existing dependencies.
- Retain the recovery/context-reconstruction and intermittent native Neon database-abort limitations documented in [v0.0.28](v0.0.28.md).
