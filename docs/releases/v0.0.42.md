# MinuChannels v0.0.42

Activity now follows the selected Workspace, with All, Mentions and Threads tabs and grouped thread replies. Thread notifications open inside their parent Conversation. This release also adds private account libraries and reviewed Workspace presets.

## Workspace-scoped Activity

- **All** combines eligible mentions and replies. **Mentions** shows direct mentions and broadcasts addressed to you, including inside threads. **Threads** shows eligible replies and mentions in threads; ordinary replies become eligible when you authored the root or had already participated.
- Multiple participants' notifications in the same thread share one row with the latest matching preview, author summary and unread-notification count. Separate threads in one Conversation remain separate, and unthreaded mentions remain individual items. Filtering and grouping happen before the page limit, not just across loaded messages.
- Activity and its navigation badge follow only the selected Workspace. The badge counts all eligible unread notifications, not grouped rows, the selected tab's subset or ordinary unread messages. Three unread replies may occupy one row but still contribute three to the badge; a mentioned reply counts once.
- The selected tab survives Back, reload and Workspace switching. Each Workspace/view has its own URL, query cache and paginated results. No reactions, app notifications, following controls or separate Threads screen are added.
- Existing `/app/activity` bookmarks resolve to the remembered accessible Workspace, or the first accessible Workspace. Browsing or switching Activity does not acknowledge messages or clear existing unread state.

## Threads in Conversation context

- Thread replies and mentions from Activity open their parent Conversation at the root and select the exact thread at its first unread reply, or the linked reply when already read.
- Desktop shows the existing side panel; mobile shows the thread full-screen. Closing returns focus to the parent root without adding a Back step. Back restores the Activity Workspace, loaded pages and scroll position, including after reload.
- Explicit notification targets override remembered panels. Parent mentions open the parent view; an unavailable thread never falls back to a different remembered thread. Older standalone thread URLs remain supported.
- The parent serving as context is not acknowledged while the requested thread loads or remains open. Thread acknowledgements keep their own visibility, focus and occlusion guards; closing restores the parent's independent guarded read behavior. Only scoped page counts and scroll coordinates are persisted for Activity restoration, not notification bodies.

The existing shared connection, 100-topic cap, inbox hints and polling recovery are unchanged; an open thread still consumes its own topic slot. See [Activity and unread state](../activity-inbox.md).

## Account libraries and reusable agents

Open **Account settings** to manage private agent templates, skills and Workspace presets. Libraries belong to the authenticated human identity, not to every administrator of a Workspace. This is not a new login, cross-device account or synchronization service.

Saves create immutable versions. Stale writes require explicit review; archival preserves history instead of deleting it. Private editor drafts survive transient refresh failures, while access denial removes private controls.

**Add from account agents** creates a fresh Workspace agent with a basic membership and an allowlisted configuration copy. Credentials, elevated roles, paths, conversation assignments, Runtime sessions and history are not copied. Later template edits do not propagate into existing agents. See [Account libraries](../account-libraries.md) and [Agent templates](../account-agent-templates.md).

## Shared skill selection

Select owned account skills or active published Workspace skills for future session instruction context. New/replacement sessions capture current selected versions; running and same-session resumed workers retain their original snapshot. These procedures are not native harness skills, automatic tool execution, permission grants or additions to the composer invocation catalog.

**Make independent copy** creates a separate published Workspace skill. Customize and explicitly select that copy when wanted; it has no upstream synchronization. Archived sources prevent new launches that still select them without rewriting running snapshots. See [Shared account skills](../shared-account-skills.md).

## Workspace presets

Review and customize a preset's starter agents, skill references, conversation presets, instructions and timing defaults before creating a Workspace. Choose its source folder separately for that creation. The new General Conversation contains only its creating human; starter agents are not implicitly assigned and no Runtime sessions start.

Workspace creation spans separate stores, not a distributed transaction. After an uncertain outcome, inspect the frozen request/receipt and explicitly retry that same intent. Reload retains its opaque request identity without storing the private plan in browser localStorage. Missing receipts do not authorize a new request; conflicting partial edits require inspection rather than overwrite. There is no automatic rollback, deletion, retry or permission escalation. See [Workspace presets](../workspace-presets.md).

## Upgrade and release gates

Upgrading from v0.0.41 adds private Relay migrations `0025_account_library`, `0026_agent_account_skills`, `0027_workspace_skill_selection` and `0028_workspace_compositions`. They add versioned account records, optional agent skill selections and durable creation intents. Public messages and human/agent read cursors are not rewritten. Earlier versions also apply their intervening migrations.

Back up the complete stopped data directory before updating, retain migration snapshots and existing Runtime resume material, and reload browser tabs afterward. Downgrading an already-migrated directory is unsupported; restore the complete pre-upgrade backup instead.

Runtime remains pinned to `f111a7981b8788fc101df064e148221caca4f102`, as in v0.0.41. Native engine requirements, permissions, local-control protocol version and dependency locks are unchanged. Existing sessions are not silently replaced; adopt changed skill selections through an explicit new/replacement session.

Require green PR, exact post-merge and tag-workflow checks, then checksum/source-pin verification and isolated acceptance of the exact uploaded artifact, including persisted reopen and a genuine Pi response. Account-library and preset persistence/recovery are additional acceptance concerns for these migrations. Prior artifact acceptance does not validate this new package. See [release guidance](../releasing.md).

Preparing these notes does not authorize tagging or publication. Publishing does not update or restart an installation.
