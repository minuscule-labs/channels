# MinuChannels v0.0.48

Create and manage scoped status API keys in **Workspace Settings → Integrations**, using the familiar Notes key-list and access-dialog pattern.

## API key management

An active human Workspace owner/admin can manage their own delegated keys: create, edit access and expiry, rotate, or revoke. Select specific Conversations and threads, or lock a key to one target. Parent grants can explicitly include existing and future threads. **Inspect status** remains the only API capability.

Creation and rotation show the secret once, with copy feedback and a manual-copy fallback. Closing or leaving the dialog clears it; secrets are excluded from query caches, browser storage and URLs. Rotation immediately invalidates the previous secret and preserves expiry. New keys default to 30 days, with a maximum of 90 days.

Conflicting edits require current-metadata review and a separate save. Keeping edits preserves newer settings the human did not change, including access reductions. A lost response or authentication denial after persistence leaves an unresolved change for explicit review, with no automatic mutation retry. Target choices load when needed with bounded thread reads, and existing unavailable grants remain visible for review.

The Connection example uses the actual loopback listener URL advertised by the authenticated control server. Older servers or failed reads retain an explicit `$CONTROL_ORIGIN` placeholder. See the [credential guide](../agent-api-credentials.md) for provisioning and headless use.

## Upgrade and limits

There are no new database migrations or Runtime changes. Back up the complete stopped data directory before updating and reload browser tabs afterward. Runtime remains pinned to `8239db90896b5ffdff1150bf781d4fb62e90fade`; local-control protocol 25 and dependency locks are unchanged.

- Non-secret unresolved intents survive dialog close and route remount within the live page, but not a full page refresh. After refreshing during an uncertain change, review current key metadata before acting again. A lost secret cannot be recovered; explicitly revoke or rotate the reviewed key.
- The API remains loopback-only status inspection. MCP, hosted access, message retrieval, message posting and agent lifecycle control are not included.
- The historical native storage shutdown issue and current restricted-thread ACL/skill limitations described in [v0.0.47](v0.0.47.md) remain applicable.

Required PR, post-merge and tag-workflow checks, checksum verification of the uploaded artifact, a clean-account installation, persisted-data reopen and a genuine Pi response remain release gates. Preparing these notes does not claim those checks have passed. Publishing does not update or restart an installation.
