# MinuChannels v0.0.30

This patch restores mention-based agent handoffs without changing human sticky recipient selection.

## Agent handoffs and human selection are independent

An agent can mention another participant's exact handle in its response to request follow-up work. The handoff reaches an eligible existing agent session in the same conversation or thread, according to the recipient's wake policy. No new messaging tool is required.

Each human keeps their own browser-local recipient selection. For example, if you selected coworker, a coworker-to-verifier handoff does not redirect your next unmentioned message: it still goes to coworker. Both agents' responses remain visible in the shared conversation.

## Safeguards and compatibility

- Agent handoffs do not start unbound agents or resume stopped agents. Existing permission, lifecycle, lease and retirement safeguards remain authoritative.
- Unaddressed agent replies never wake peers, including under `all_messages`. Self messages do not create another turn; muted recipients remain muted.
- Intentional mentions exclude code, quotations and escaped text. Unknown or disabled recipients retain existing validation.
- Supplied API `to` remains authoritative, including `[]`. When it is omitted, intentional body mentions resolve recipients for humans and agents. Agent-response mentions once again resolve handoff recipients.
- Threads retain separate sessions, messages and frozen inherited context.
- Runtime remains pinned to `f0ffbfcc5f24e75174bff1919aa5cd41ce22d732`; local-control protocol stays **24**. No dependency or database migration changes.
- The recovery/context-reconstruction and intermittent native Neon database-abort limitations from [v0.0.28](v0.0.28.md) remain. This patch does not claim to fix them.
