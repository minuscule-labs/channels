# MinuChannels v0.0.15

**Prepared release — not yet published.** Compared with **v0.0.14**, this update adds a safe way to inspect recent Runtime activity without exposing raw agent logs.

## Recent Runtime events

Workspace owners and admins can open **Details & diagnostics → Recent Runtime events** for an agent, then choose **Show events** or **Refresh events**.

The view shows what Runtime observed:

- Turn acceptance, reuse and conflicting-input rejection.
- Dispatch requests, returns and failures.
- Runtime turn results.
- Steering and interruption requests, acknowledgments and failures.
- Stop requests and bridge readiness.

The existing Channels operation timeline remains the place to inspect routing, session lifecycle and cleanup observations. Runtime acknowledgments do not prove that a turn settled, a process exited or a reply reached the public Conversation.

## Bounded and private

- Each snapshot contains at most **200 structured events** and **32 KiB**, with a two-second resource-read deadline.
- Capture time, the current worker's recording window and evicted-event counts make coverage visible. A restarted worker begins a new window; this is not durable session history.
- Reads are scoped to the authorized human, Workspace, Conversation, participant and exact owned session. Changed or revoked access suppresses late results.
- Events are read only when explicitly opened or refreshed. Closing, navigation, access loss and observed session changes clear the disposable view.
- No raw Pi/Codex logs, prompts, credentials, tool output, private paths or native identifiers are included. Events stay out of diagnostic reports, clipboard actions, browser storage and cross-tab caches.
- Unsupported or unavailable workers show **Unavailable**. Inspection does not start, resume or wake an agent. Older running workers may lack this capability; upgrading Channels does not retrofit or restart them.

This update pins merged Runtime `e92176054206d70e120d4b6641bda2a3d037eb84` and uses local-control protocol **21**. It adds no database migration and does not change Start, Stop, replacement or recovery behavior.

## Verification and known limitations

The feature merged in [Channels PR #44](https://github.com/minuscule-labs/channels/pull/44), following [Runtime PR #10](https://github.com/minuscule-labs/runtime/pull/10). Feature and merged-main CI passed Ubuntu/macOS verification, Chromium regression and release packaging. The delegated code review approved the integration with no actionable findings; its focused checks were independent, while full browser/package evidence remained author/CI evidence.

Local feature verification passed **260 backend/storage tests**, **151 web unit tests**, **107 Chromium tests**, clean-clone package build/pack/smoke and five production-preview browser cases. Additional checks exercised the packaged Runtime client through Channels HTTP authorization and temporary SQLite with deterministic callbacks. See [structured feature evidence](../verification/agent-diagnostics-recent-events.json). These results cover the feature target, not a claim that an unpublished v0.0.15 artifact has passed release acceptance.

- Versioned v0.0.15 packaging and release-PR CI must pass before publication.
- Fresh genuine-Pi and clean-account installed-artifact acceptance remain outstanding. Release completion requires the [documented acceptance](../local-release.md#verification); automated and fake-RPC checks do not replace it. Running real agents requires separate scoped approval.
- The earlier intermittent native database-related crash still has no proven root cause. This release does not claim to fix it.
- MinuChannels remains a single-user, loopback-only local alpha for macOS and Linux. Do not expose its ports to other machines or untrusted local users.
- Raw-log downloads, transcript exports, image support, session branching and automatic recovery are not included.

## Installing or upgrading after publication

Download `minu-channels-0.0.15.tgz` and `SHA256SUMS` from the approved GitHub Release and verify the checksum before installing:

```bash
npm install -g ./minu-channels-0.0.15.tgz
```

Follow [installation and upgrade guidance](https://github.com/minuscule-labs/channels/blob/v0.0.15/docs/local-release.md) to coordinate an existing instance and back up its data. This release preparation does not upgrade or restart any installation.
