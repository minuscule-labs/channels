# MinuChannels v0.0.29

This patch simplifies the composer and message menus without changing Runtime, agent recovery or stored conversation data.

## A quieter composer

- Remove the recipient dropdown entirely, with no replacement indicator or helper text.
- Keep attachment on the left and Send on the right in main conversations and threads.
- Mention a participant to choose or switch recipients. Ordinary follow-ups keep that selection, separately for each human and conversation/thread in the current browser.
- Preserve thread-root defaults, Send-triggered startup, exact retry targets, permissions and archive restrictions. Broadcasts and multiple recipients remain message-only overrides; incoming messages and generated replies do not redirect a person's selection.

## Thread-only message menus

Message popups now offer only **Start thread** or **Open thread**. The separate **Reply** action and thread-root Reply button are removed. Thread messages no longer show an otherwise empty actions menu.

Threads retain separate messages, drafts, agent sessions and frozen inherited context. Existing saved reply/retry metadata and backend/API reply support remain compatible; this patch does not rewrite message history.

## Compatibility and known limitations

- Runtime remains pinned to `f0ffbfcc5f24e75174bff1919aa5cd41ce22d732`; local-control protocol stays **24**. No dependency or database migration changes.
- Recipient preferences remain browser-local. They are not copied into another browser profile or incognito session.
- Fresh browser sign-in and development/production cookie isolation are separate backlog work, not fixes included in this patch. CI/CD behavior is unchanged.
- The recovery/context-reconstruction and intermittent native Neon database-abort limitations from [v0.0.28](v0.0.28.md) remain. This patch does not claim to fix them.
